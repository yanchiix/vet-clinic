# API-GATE: готовність OpenAPI-контракту

## Мета й межі

Цей документ оцінює технічну готовність API-first baseline за пунктами 1–14 порядку виконання роботи. Це контрольний список, сформований для цієї оцінки, а не раніше затверджені проєктні критерії API-GATE. Технічна оцінка сама по собі не є рішенням Human GO/REVISE і не підтверджує реалізацію бізнес-поведінки; окреме рішення наведено нижче.

Оцінювання спирається на `api/openapi.yaml`, `docs/contract-testing.md`, матрицю простежуваності та затверджені SRS v0.1 і ADD-001. Результати lint і mock наведено за наданими доказами; повторний запуск інструментів не виконувався.

## Відомі обмеження

- 56 Redocly warnings належать до `no-required-schema-properties-undefined` у композиційних схемах з умовними `required`. Це прийняті warnings; відповідні умовні обмеження ще не підтверджені на реальному backend.
- Prism mock не реалізує бізнес-правила, не перевіряє збереження даних, рольову авторизацію, конкурентні операції чи інтеграції. 14 smoke-сценаріїв дають лише обмежене покриття HTTP-контракту.
- Для `POST /auth/client-sessions` HTTP 422 є фактичною поведінкою Prism на некоректному тілі. Ця операція не декларує 422 в OpenAPI, тому код не є гарантією API або backend.
- Наведене нижче Human GO стосується лише API-first baseline; воно не підтверджує реалізацію backend чи інтеграцій.

## Висновок

**READY FOR API-FIRST BASELINE** — надані докази підтверджують наявність і технічну валідність OpenAPI-контракту та базову перевірку вибраних сценаріїв через Prism. Висновок діє лише з наведеними обмеженнями та не означає готовність backend або виконання всіх вимог.

G03 Integrity Gate — окремий, ширший контрольний етап. Він залишається відкритим до реалізації та інтеграційного тестування, включно з належними доказами й окремим рішенням Human.
